A.5.5 HUGGING FACE READ TOKEN  (recommended, optional)               [ ] 5 min
     Why: BioCLIP2 download (D.1) emitted "anonymous request" warnings.
     Without a token:
       - Anonymous rate limit (~10 req/hr per IP)
       - Slower downloads (lower priority queue)
       - Cannot access "gated" models (none in our current plan, but
         SAM, DINOv2, LLaMA-vision etc. would require it if added later)
     With a token:
       - Higher rate limits (1000+ req/hr)
       - Cleaner audit trail in HF activity log
       - Future-proof for any gated model in stretch goals
     Steps:
       1. Go to https://huggingface.co/settings/tokens
       2. New token -> Type=Read -> any name (e.g., "fathomnet-2026")
       3. Copy the token (starts with "hf_...")
       4. Paste into .env as: HUGGINGFACE_HUB_TOKEN=hf_<your_token>
       5. (Optional) Set as Windows User env var so it persists:
          [Environment]::SetEnvironmentVariable("HUGGINGFACE_HUB_TOKEN", "hf_...", "User")
       6. Verify: python -c "from huggingface_hub import HfApi; print(HfApi().whoami())"
          Should print your HF username + email instead of erroring.
     If skipped: BioCLIP2 download still worked tonight; this just removes
     warnings and prepares for any future model needs.

W&B (Weights & Biases) usage protocol (added May 1, 2026):

  W1  EVERY training script (Phase 2-7) starts with:
        wandb.init(
          entity="navya2392-usc",
          project="fathomnet-2026",
          name=f"<phase>_<exp>_<model>_<imgsz>_<seed>",   # e.g. "p2_yolo11m_baseline_640_42"
          tags=["<phase>", "<exp_id>"],
          config={
            "model": "yolo11m", "imgsz": 640, "epochs": 50, "batch": 16,
            "lr": 0.01, "fold": 0, "seed": 42,
            # any other hparam that varies between runs
          },
        )
      Run name pattern lets us filter the W&B dashboard by phase/experiment.

  W2  EVERY training loop logs at minimum (per epoch):
        wandb.log({
          "train/box_loss": ..., "train/cls_loss": ..., "train/dfl_loss": ...,
          "val/mAP_50_95": ..., "val/mAP_50": ...,
          "val/per_class_AP": wandb.plot.bar(...),     # 32-class breakdown
          "epoch": e, "lr": current_lr,
        }, step=e)
      Use Ultralytics' built-in W&B logging where possible (it's enabled
      automatically when wandb is installed); customize via callbacks for
      per-class AP and any custom metrics (PU loss, EFL terms).

  W3  AT END of every promising run, save artifacts:
        wandb.save("best.pt")                          # uploads weights as artifact
        wandb.log({"final/val_mAP": ..., "final/lb_mAP": ...})   # if known
      Artifact lets us rebuild any past model from W&B without manual scp.

  W4  EVERY Kaggle submission gets a NOTE on its W&B run:
        wandb.run.notes = f"Submitted to Kaggle. LB mAP={lb_score:.4f}"
      Lets us correlate val mAP vs LB mAP across runs (gap is informative
      about overfitting / pseudo-label noise).

  W5  RUN GROUPING: use wandb.group="phase{N}" to keep phases visually
      organized in the dashboard. wandb.job_type="train"|"predict"|"ensemble"
      separates training from inference/prep runs.

  W6  COST DISCIPLINE: kill failed/throwaway runs immediately
      (wandb.run.delete()) so the dashboard stays signal-rich, not noisy.
      Every run committed to history should be one we'd cite in the
      working notes paper (K.1).
