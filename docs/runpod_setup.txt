--------------------------------------------------------------------------------
  PART A  -  ONE-TIME ACCOUNT & TOOLING SETUP   (~15 minutes)
--------------------------------------------------------------------------------

A1. CREATE RUNPOD ACCOUNT
    - Go to https://runpod.io  ->  Sign Up
    - Verify your email.

A2. ADD CREDIT
    - Top-right account menu  ->  Billing  ->  Add Credit
    - Add $100 to start (matches v5 plan step 3).
      You can top up later in $25 increments. Unused credit does NOT expire.
    - Optional: Settings -> Notifications -> set spend alerts at $100 and $200.

A3. GENERATE A LOCAL SSH KEY (Cursor Remote-SSH will use this)
    Run in PowerShell:

        ssh-keygen -t ed25519 -C "fathomnet-2026" -f $HOME\.ssh\runpod_ed25519

    Press Enter for empty passphrase (this is an ephemeral cloud key).
    Two files appear in C:\Users\navya\.ssh\:
        runpod_ed25519        (private - keep secret)
        runpod_ed25519.pub    (public - paste into RunPod)

A4. UPLOAD PUBLIC KEY TO RUNPOD
    Print the public key:

        Get-Content $HOME\.ssh\runpod_ed25519.pub

    Copy the entire single line ("ssh-ed25519 AAAA... fathomnet-2026").
    In RunPod: Settings -> SSH Public Keys -> Add Public Key -> paste -> Save.

A5. INSTALL CURSOR REMOTE-SSH EXTENSION
    Cursor -> Extensions panel (Ctrl+Shift+X) -> search "Remote - SSH" ->
    install the Microsoft one. After install, the green "><" icon appears
    bottom-left.


--------------------------------------------------------------------------------
  PART B  -  REUSABLE POD TEMPLATE   (configure once, redeploy as needed)
--------------------------------------------------------------------------------

Every pod you launch for this project uses the same recipe; only the GPU type
and cloud type change between phases.

  Setting               Value
  -------               -----
  Template              runpod/pytorch:2.4.0-py3.11-cuda12.4.1-devel-ubuntu22.04
                        (or latest runpod/pytorch image - PyTorch + CUDA preinstalled)
  Container disk        30 GB           (ephemeral; for pip installs, scratch)
  Volume disk           80 GB           (PERSISTENT, mounted at /workspace)
  Volume mount path     /workspace
  Cloud type            see Part C - varies by phase
  Region                cheapest with the GPU you want (US-OR / EU-RO usually best)
  Expose ports          TCP 22  (Cursor Remote-SSH connects via SSH)
  SSH key               select the runpod-ed25519 key from A4

WHY a persistent volume?
  - Pods stop and start; a stopped pod still keeps /workspace.
  - You download data ONCE (~25 GB) and reuse across all 5 paid phases.
  - Stopped-pod cost: only ~$0.07/GB/month for the volume = ~$5/mo for 80 GB.
  - Running-pod cost: full GPU rate, billed by the second.

FIRST-LAUNCH BOOTSTRAP (run once, on pod, after deploying first time):

    cd /workspace
    git clone <YOUR_REPO_URL_HERE> fathomnet-2026
    cd fathomnet-2026
    pip install -r requirements.txt

    # Push your data up from local (faster than re-downloading on the pod):
    # On your LOCAL machine, in PowerShell, after pod is running:
    # rsync or scp the data/raw folder to /workspace/data/raw on the pod.
    # Connection string is shown in RunPod -> Pods -> Connect -> SSH over exposed TCP.

--------------------------------------------------------------------------------
  PART D  -  WHICH GPU AND WHY NOT THE OTHERS
--------------------------------------------------------------------------------

RTX 4090 (24 GB)        Workhorse. ~$0.34-0.50/hr community.
                        ~80% of A100 throughput at ~1/3 the cost.
                        Use whenever batch size fits in 24 GB.
                        Phases 3, 4, 7 -> always 4090.

A100 40GB               Use only when you need uptime guarantees (Phase 6)
                        OR when 24 GB isn't enough VRAM for the model.
                        ~$1.19-1.89/hr.

A100 80GB               Use only for SSL pretraining (Phase 1) where giant
                        batch sizes (>=512) materially help contrastive
                        learning. ~$1.69-2.49/hr.

H100 80GB               DO NOT RENT for this project. ~$2.49-3.99/hr
                        for ~1.7x the speed of a 4090 on YOLO/RT-DETR.
                        Bad value at our scale.

SECURE vs COMMUNITY     Secure: guaranteed uptime, ~50% more expensive.
                        Community: cheaper, can be reclaimed by the host.
                        Use SECURE only for runs > 24 hours where
                        a preemption would cost meaningful money to redo.


--------------------------------------------------------------------------------
  PART E  -  COST DISCIPLINE   (this is where people blow budget)
--------------------------------------------------------------------------------

E1. STOP THE POD WHEN NOT TRAINING
    A "stopped" pod charges only for the persistent volume (~$5/month for 80 GB).
    A "running" pod charges full GPU rate even when idle.
    Habit: when a training run finishes, immediately Pods -> Stop.

E2. RUN ONE TRAINING PROCESS PER POD
    Don't leave a Jupyter kernel hot "for later". Don't ssh in to "check on it"
    and leave the connection open with a python REPL. Both leak GPU-hours.

E3. CHECKPOINT TO /workspace/weights/ AFTER EVERY PROMISING RUN
    Pods can be terminated. Volumes survive. Saving a 200 MB .pt costs nothing
    and lets you resume any phase without re-renting.

E4. STREAM LOGS TO W&B IN REAL TIME
    If a pod dies mid-run you keep the metrics. Set:
        wandb.init(project="fathomnet-2026", resume="allow")

E5. ENABLE SPEND NOTIFICATIONS
    RunPod -> Settings -> Notifications -> alerts at $100 and $200.
    Optional: hard-cap your credit (don't enable auto-recharge).

E6. DON'T RENT FOR PHASE 0
    Phase 0 (this notebook + JSON EDA + the configs you generate) is LOCAL,
    no GPU, $0. Don't burn credit while you're still slicing JSONs.
    First rental fires in PHASE 3, after the free Kaggle baselines.


--------------------------------------------------------------------------------
  PART F  -  CONNECTING CURSOR TO A RUNNING POD
--------------------------------------------------------------------------------

After deploying a pod (any phase):

F1. RunPod -> My Pods -> click your pod -> Connect -> SSH over exposed TCP
    Copy the connection string. It looks like:
        ssh root@69.30.85.123 -p 22183 -i ~/.ssh/id_ed25519

F2. Open Cursor. Press Ctrl+Shift+P -> "Remote-SSH: Connect to Host..."
    -> Add New SSH Host -> paste the ssh command above (replace -i path
    with $HOME\.ssh\runpod_ed25519).
    Cursor saves it to C:\Users\navya\.ssh\config.

F3. Reconnect via Ctrl+Shift+P -> "Remote-SSH: Connect to Host..." ->
    pick the saved entry. Cursor opens a new window connected to the pod.

F4. File -> Open Folder -> /workspace/fathomnet-2026
    All Cursor features (Composer, Tab, agents) now run against the pod's
    filesystem and GPU. Local agents in this OneDrive folder are unaffected.

F5. When done for the day:
    - Close the Cursor remote window.
    - In RunPod web UI, Pods -> Stop.
      (Don't "Terminate" - that deletes the volume too.)
